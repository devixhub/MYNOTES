DAY-1

DOCKER ARCHITECTURE
-------------------

First, we take a Linux server, for example an Ubuntu machine,
and install Docker on it.

Once Docker is installed, that complete machine is called the
Docker Host.

Inside the Docker Host, Docker mainly has two components:

1. Docker Server (Docker Daemon)
   The Docker Server is responsible for performing Docker operations
   such as creating containers, building images, starting and stopping
   containers, etc. It also manages local Docker images and containers.

2. Docker Client (CLI)
   The Docker Client is where we execute Docker commands such as:

   docker build
   docker run
   docker create
   docker start
   docker stop
   docker push
   docker pull

When we execute these commands through the Docker Client, the request
goes to the Docker Server, and the Docker Server performs the required
operation.


DOCKER CLIENT
-------------

Inside the Docker Client side, we create a Dockerfile.

The Dockerfile is a text file in which we specify what our application
needs.

For example:

Ubuntu
Java
Python
Maven

So the Dockerfile tells Docker:

"I need an Ubuntu environment, and inside that environment I need
Java, Python and Maven."


DOCKER BUILD
------------

After creating the Dockerfile, we use:

docker build -t myenv:v1 .

The docker build command reads the instructions from the Dockerfile
and starts creating the required environment.

When we execute docker build, Docker reads the Dockerfile and executes
the instructions step by step.

During the build:

1. Docker creates a temporary container.
2. Required operations are performed inside it.
3. Each step creates a filesystem layer.
4. After all steps are completed, these layers form the final
   Docker image.
5. The temporary container is removed.


DOCKER IMAGE
------------

The final result of docker build is a Docker Image.

Example:

myenv:v1

myenv -> image name
v1    -> image tag/version

The image contains everything specified in the Dockerfile.

Layers:

Layer 4 -> Maven
Layer 3 -> Python
Layer 2 -> Java
Layer 1 -> Ubuntu


DOCKER RUN
----------

Once the image is available:

docker run myenv:v1

The purpose of docker run is to create and start a container
from the Docker image.

Docker run is used to create and start a container from an image.

We can create multiple containers from the same Docker image.

The image can be the same, but each container gets a different
container ID.

Example:

Docker Image: myenv:v1

docker run myenv:v1
    -> Container C1

Run again:

docker run myenv:v1
    -> Container C2

Run again:

docker run myenv:v1
    -> Container C3

The image remains the same, but every newly created container
gets its own unique container ID.


DOCKER PUSH
-----------

Suppose we have created:

myenv:v1

and we want to share it with another developer.

We use:

docker push myenv:v1

The purpose of docker push is to upload/share a Docker image
to a remote registry.

The image is uploaded from our Docker Host to Docker Hub /
remote registry.


DOCKER PULL
-----------

Now imagine another developer has another Docker Host.

That developer needs the same image.

They can use:

docker pull username/myenv:v1

After the image is downloaded, the developer can create a
container from it.


============================================================
                  WHAT IS DOCKER?
============================================================

Docker is a containerization platform.

It packages an application and all its required dependencies
into a container so that the application can run consistently
in different environments.

Example:

Application
    |
    +-- Java
    +-- Python
    +-- Maven
    +-- Other dependencies
    |
    ---> Docker Container


============================================================
                WHY DO WE NEED DOCKER?
============================================================

PROBLEM 1
---------

Suppose we have multiple applications.

APP-1 requires Java 8
APP-2 requires Java 11

If both applications are deployed on the same machine,
they may have dependency or version conflicts.

Example:

APP-1 -> Java 8
APP-2 -> Java 11

Both applications may not work properly because they require
different Java versions.


PROBLEM 2
---------

Different applications may require different versions of the
same software.

Example:

Application 1 -> Java 8
Application 2 -> Java 11
Application 3 -> Java 17

Managing different versions on one machine can create
dependency problems.


PROBLEM 3
---------

RESOURCE UTILIZATION

Suppose a machine has 8 GB RAM.

One application may use only 500 MB RAM.

The remaining resources may not be properly utilized.

If another application is deployed on the same machine,
there can be resource and dependency issues.

Also, when one application is running, it may affect
other applications.


============================================================
                     VIRTUALIZATION
============================================================

To solve these problems, companies use virtualization.

Virtualization allows us to create multiple Virtual Machines
(VMs) on a single physical machine.

A software called a HYPERVISOR is used to create and run
Virtual Machines.

HYPERVISOR
----------

A hypervisor is software that allows us to create and run
Virtual Machines on a physical machine.

Example:

PHYSICAL MACHINE
       |
   HYPERVISOR
   /    |    \
  /     |     \
VM-1   VM-2   VM-3
 |       |      |
OS-1   OS-2   OS-3
 |       |      |
APP-1  APP-2   APP-3


ADVANTAGES OF VIRTUALIZATION
----------------------------

1. We can run different operating systems on one physical machine.
2. We can deploy multiple applications.
3. Applications can have different OS environments.
4. We can use different versions of software.
5. Better isolation between applications.
6. Multiple environments can be created on one physical machine.


DISADVANTAGES OF VIRTUALIZATION
------------------------------

1. Each VM needs its own operating system.
2. Each VM requires CPU and RAM.
3. More resources are consumed.
4. There is resource overhead because every VM has a complete OS.
5. VM creation and management can be heavier.
6. Hardware resources may not be efficiently utilized.

Example:

Physical Machine = 8 GB RAM

VM-1 -> 2 GB RAM
VM-2 -> 2 GB RAM
VM-3 -> 2 GB RAM

A significant amount of memory is consumed by the operating
systems themselves.

============================================================
                      DOCKER RUN
============================================================

docker run is used to create and start a new container
from a Docker image.

Important note from practice:

It will pull the image from Docker Hub and download it
to the local registry if the image is not available locally.

When we do the second run, Docker does not go to the
central/public registry first.

It searches the local registry first.

Example:

docker run -it centos

Here:

docker run = create and start a new container
-it        = interactive terminal
centos     = image name

Another example:

docker run -it centos:7

Here:

centos = image
7      = tag/version


============================================================
                DOCKER RUN VS DOCKER START
============================================================

docker run:

- Creates a NEW container from an image.
- Starts that new container.

Example:

docker run -it centos

If we execute docker run again:

docker run -it centos

another NEW container will be created.

The image can be the same, but the container ID will be different.


docker start:

- Starts an EXISTING stopped container.
- It does NOT create a new container.

Example:

docker start <container_id>


IMPORTANT:

docker run
-> Create + Start NEW container

docker start
-> Start EXISTING stopped container


============================================================

============================================================

-t means allocate a terminal.

Together:

-it

Example:

if we want to go out of the container but keep the container

If we want to detach from the container while keeping it running:

This detaches from the container without stopping it.

============================================================
             COMMAND-BY-COMMAND EXPLANATION
============================================================

sudo docker run -it centos
-> Downloads the CentOS image if it is not available locally,
   then creates and starts a container.
-> -it = interactive terminal, so you can enter commands inside
   the container.

sudo docker run -it centos:7
-> Runs a CentOS version 7 container interactively.
-> centos:7 means image name = centos and tag/version = 7.

clear
-> Clears the terminal screen.
-> It does not affect Docker containers or images.

sudo docker ps
-> Lists currently running Docker containers.
-> It shows container ID, image, status, ports and name.

sudo docker attach fa671c640475
-> Connects your terminal to the running container with this ID.
-> You can interact with the process running inside the container.

sudo docker ps
-> Checks which containers are currently running.
-> The attached container should appear if it is still running.

sudo docker ps -a
-> Lists all containers on the Docker Host.
-> Includes running, stopped and exited containers.

sudo docker start fa671c640475
-> Starts the existing stopped container with this ID.
-> It does not create a new container.

sudo docker ps
-> Checks whether the started container is now running.

sudo docker attach fa671c640475
-> Attaches your terminal to the existing running container.
-> Allows you to interact with that container again.

clear
-> Clears the terminal screen.
-> No Docker resource is changed.

sudo docker run -itd centos:7
-> Creates and starts a new CentOS 7 container in the background.
-> -i = interactive
-> -t = terminal
-> -d = detached/background mode.

sudo docker ps
-> Lists the running containers.
-> The newly created CentOS container should appear.

sudo docker ps -a
-> Lists all containers.
-> Shows both running and stopped/exited containers.

sudo docker rm a07745b4fe63 fa671c640475 c6fe5218dc35 88432bab8e60 80df1dfaf231
-> Removes the specified containers.
-> Normally containers must be stopped before removal.
-> docker rm -f can be used for intentional force removal.

sudo docker ps
-> Shows currently running containers.
-> Removed containers will not appear.

sudo docker stop a07745b4fe63
-> Gracefully stops the running container with this ID.
-> The container is stopped but still exists.

sudo docker rm a07745b4fe63
-> Removes the stopped container.
-> The container is deleted, but its image is not deleted.

sudo docker ps -a
-> Checks all remaining containers.
-> The removed container should no longer appear.

clear
-> Clears the terminal screen.
-> It does not change Docker resources.

sudo docker run -itd centos:7
-> Creates and starts another CentOS 7 container in detached mode.
-> If the image already exists locally, Docker uses the local image.

sudo docker ps -a
-> Lists all containers.
-> You can see the newly created CentOS 7 container and its status.

sudo docker images
-> Lists Docker images stored locally.
-> Shows repositories, tags, image IDs and sizes.

sudo docker rmi centos:7
-> Removes the CentOS 7 image from the local image store.
-> It will fail if a container still depends on that image.

sudo docker ps
-> Lists running containers.
-> It does not list Docker images.

sudo docker rmi centos:7
-> Tries to remove the CentOS 7 image again.
-> If a container still references the image, Docker normally
   refuses the removal.

sudo docker ps -a
-> Lists all containers including stopped containers.
-> Use this to find containers that may reference centos:7.

sudo docker rm 61cd5221e4ca
-> Removes the specified container.
-> After removing it, the CentOS image may become removable if
   no other container references it.

sudo docker rmi centos:7
-> Removes the CentOS 7 image if no containers are using it.

sudo docker images
-> Lists the remaining local Docker images.
-> centos:7 should no longer be listed.

sudo docker rmi hello-world
-> Removes the hello-world image from the local image store.
-> It does not remove containers created from that image.

clear
-> Clears the terminal screen.
-> Docker resources remain unchanged.

sudo docker images
-> Lists all Docker images available locally.
-> Check whether httpd, tomcat, jenkins, etc. are present.

sudo docker run -itd httpd
-> Creates and starts an Apache HTTP Server container in
   detached mode.
-> If httpd is not local, Docker pulls the image from the
   configured registry, commonly Docker Hub.

sudo docker ps
-> Lists currently running containers.
-> The httpd container should appear if it started successfully.

sudo docker run -itd tomcat
-> Creates and starts a Tomcat container in detached mode.
-> Docker pulls the Tomcat image if it is not available locally.

sudo docker run -itd jenkins
-> Creates and starts a Jenkins container using the requested
   jenkins image/tag.
-> If the image is not local, Docker attempts to pull it.

sudo docker run -itd jenkins2.x
-> Tries to run an image named jenkins2.x.
-> If that image does not exist locally or in the configured
   registry, the command will fail.

sudo docker run -itd jenkins 2.x
-> Docker interprets "jenkins" as the image and "2.x" as an
   extra argument.
-> This is not the correct way to specify a Jenkins version.

clear
-> Clears the terminal screen.
-> No Docker resource is changed.

sudo docker run -itd jenkins:2.60.3
-> Creates and starts a Jenkins container using the specific
   image tag 2.60.3.
-> jenkins = repository/image name
-> 2.60.3 = image tag/version.

sudo docker ps
-> Lists the currently running containers.
-> Verify whether the Jenkins container is running.

history
-> Displays commands previously executed in the shell.

DAY-4
========================
DOCKER COMMANDS
========================

1. CREATE CONTAINER
-------------------
COMMAND:
********
sudo docker run -itd --name myos centos:7
********
Work: Creates and starts a CentOS 7 container named myos.

GENERAL:
********
sudo docker run -itd --name containername imagename
********


2. CONTAINER LOGS
-----------------
COMMAND:
********
docker logs -f container_id
********
Work: Shows container logs continuously.
-f = Follow logs


3. EXECUTE COMMAND
------------------
COMMAND:
********
docker exec container_id COMMAND
********
Work: Executes a command inside a running container.

Example:
********
docker exec test ls /tmp
********
Work: Lists /tmp inside the test container.


4. ENTER CONTAINER
------------------
COMMAND:
********
docker exec -it test /bin/bash
********
Work: Opens Bash shell inside the running container.


5. CREATE FILE
--------------
COMMAND:
********
docker exec test touch /tmp/testfile
********
Work: Creates testfile inside container /tmp.

Check:
********
docker exec test ls /tmp
********


6. COPY HOST → CONTAINER
------------------------
COMMAND:
********
docker cp myfile test:/tmp
********
Work: Copies myfile from host to /tmp inside test container.

GENERAL:
********
docker cp <hostfile> <container_id>:<path>
********


7. COPY CONTAINER → HOST
------------------------
COMMAND:
********
docker cp test:/tmp/myfile /tmp/myfile
********
Work: Copies myfile from container to host.

GENERAL:
********
docker cp <container_id>:<path> <hostfile>
********


8. ENVIRONMENT VARIABLE
-----------------------
COMMAND:
********
docker run -it -e mycompany=techm centos /bin/bash
********
Work: Creates CentOS container and sets mycompany=techm.

Check:
********
echo $mycompany
********


9. WORKING DIRECTORY
--------------------
COMMAND:
********
docker run -it -w /tmp centos /bin/bash
********
Work: Starts the container with /tmp as the working directory.

-w = Working directory

DAY-4
========================
VOLUME MAPPING
========================
WHY?
Container data can be lost when a container is deleted. Volume mapping stores important data outside the container so it can persist.

BASIC IDEA:
HOST /tmp/test  ─────→  CONTAINER /tmp

1. BASIC VOLUME MAPPING
------------------------
COMMAND:
********
sudo docker run -itd -v /tmp/test:/tmp --name myos2 centos
********
Work: Creates CentOS container "myos2" and maps HOST /tmp/test → CONTAINER /tmp.

-v HOST_PATH:CONTAINER_PATH
LEFT  = Host path
RIGHT = Container path

Example:
-v /backup/data:/data
/backup/data (Host) → /data (Container)

2. APPLICATION PATH
-------------------
Applications have their own data directory. We can map host storage directly to that application path.

Apache application path:
/usr/local/apache2/htdocs

COMMAND:
********
sudo docker run -itd -p 8085:80 -v /tmp/test:/usr/local/apache2/htdocs --name mywebserver1 httpd
********
Work: Runs Apache and maps HOST /tmp/test → Apache's web-root directory.

Flow:
Browser → HOST:8085 → Container:80 → Apache → /usr/local/apache2/htdocs
                                                   ↑
                                              /tmp/test (Host)

NOTE:
For the official httpd image, use:
/usr/local/apache2/htdocs

3. PORT + VOLUME MAPPING
------------------------
PORT MAPPING:
********
-p 8085:80
********
Host port 8085 → Container port 80

VOLUME MAPPING:
********
-v /tmp/test:/usr/local/apache2/htdocs
********
Host directory → Container application directory

So one command can perform both port mapping and volume mapping.

========================
DOCKER NAMED VOLUME
========================
Instead of providing our own host directory, Docker can create and manage the storage. This is called a Named Volume.

4. LIST VOLUMES
---------------
COMMAND:
********
sudo docker volume ls
********
Work: Lists Docker-managed volumes.

5. CREATE VOLUME
----------------
COMMAND:
********
sudo docker volume create volumename
********
Work: Creates a Docker-managed volume.

Docker normally stores volumes under:
/var/lib/docker/volumes/

6. CREATE test1 VOLUME
----------------------
COMMAND:
********
sudo docker volume create test1
********
Work: Creates a named volume called "test1".

Data location:
/var/lib/docker/volumes/test1/_data

7. CHECK VOLUME DATA
--------------------
COMMAND:
********
cd /var/lib/docker/volumes/test1/_data
********
Work: Opens the actual data directory of volume "test1".

8. ATTACH NAMED VOLUME
----------------------
COMMAND:
********
sudo docker run -itd -v test1:/tmp --name myos3 centos
********
Work: Creates CentOS container "myos3" and mounts Docker volume "test1" → /tmp.

Flow:
Docker Volume test1
        ↓
/var/lib/docker/volumes/test1/_data
        ↓
Container /tmp

========================
BIND MOUNT vs NAMED VOLUME
========================

BIND MOUNT:
********
-v /tmp/test:/tmp
********
We provide the HOST directory.
Host directory → Container path

NAMED VOLUME:
********
-v test1:/tmp
********
Docker manages the storage.
Docker volume → Container path

EASY MEMORY:
Bind Mount = "Docker, use MY directory."
Named Volume = "Docker, CREATE and MANAGE the storage."

INTERVIEW ANSWER:
Volume mapping connects external storage to a path inside a container and helps persist application data even when containers are deleted or recreated.

DOCKER IMAGE FULL LIFE CYCLE – INTERVIEW SUMMARY


I started with the official HTTPD image and created a container from it.
sudo docker run -itd --name myhttpd -p 80:80 httpd

Then I added my custom application content, such as an index.html,
inside the running container using docker cp.
sudo docker cp index.html myhttpd:/usr/local/apache2/htdocs/index.html

After making the required changes, I used docker commit to create
a new Docker image from the modified container.
sudo docker commit myhttpd myprojects:v1.0

Then I used docker tag to give the image a Docker Hub repository name
and version, for example:
sudo docker tag myprojects:v1.0 quantumdevi/myprojects:v1.0

The tag does not create a new image; it gives the same image another
name/tag.
After that, I logged in to Docker Hub and used docker push to upload
the image.
Finally, I can use docker pull to download the image on another
Docker host and docker run to create a new container from it.
