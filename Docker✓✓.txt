:::::::::::::::::::::::;::::::::::::::::::::::::::DOCKER Architecture:::::::::::::::::::::::::::::::::::::::::::::::::::::::::
First, we take a Linux server, for example an Ubuntu machine, and install Docker on it.
Once Docker is installed, that complete machine is called the Docker Host.
Inside the Docker Host, Docker mainly has two components:
1/-Docker Server (Docker Daemon)
The Docker Server is responsible for actually performing Docker operations such as creating containers, building images, 
starting and stopping containers, etc. It also manages the local Docker images and containers.
Docker Client (CLI)
The Docker Client is where we execute Docker commands such as:
docker build
docker run
docker create
docker start
docker stop
docker push
docker pull

When we execute these commands through the Docker Client, the request goes to the Docker Server, 
and the Docker Server performs the required operation.

2. Docker Client 
Now, inside the Docker Client side, we create a Dockerfile.
The Dockerfile is a text file in which we specify what our application needs.

For example we can specify: WE NEED
Ubuntu
Java
Python
Maven
So the Dockerfile tells Docker->I need an Ubuntu environment, and inside that environment I need Java, Python and Maven."
Docker Build

3 DOCKER-BUILD
After creating the Dockerfile, 
we use the docker build command EXAMPLE :docker build -t myenv:v1 .
The docker build command reads the instructions from the Dockerfile and starts creating the required environment.

When we execute docker build, Docker reads the Dockerfile and executes the instructions step by step. 
During the build, Docker creates a temporary container and performs the required operations inside it. 
Each step creates a filesystem layer. After all the steps are completed, these layers are combined to form the final Docker image, 
and the temporary container is removed.

4.Docker Image
The final result of docker build is a Docker Image.  example:myenv:v1
myenv → image name
v1    → image tag/version
The image contains everything that we specified in our Dockerfile, such as:
Layer 4 → Maven
Layer 3 → Python
Layer 2 → Java
Layer 1 → Ubuntu

5. Docker Run
Once the image is available, we use: docker run myenv:v1 The purpose of docker run is to create and start 
a container from the Docker image.

DOCKER RUN IS USED TO CREATE AND START A CONTAINER FROM AN IMAGE. 
WE CAN CREATE MULTIPLE CONTAINERS FROM THE SAME DOCKER IMAGE. THE IMAGE CAN BE THE SAME, 
BUT EACH CONTAINER GETS A DIFFERENT CONTAINER ID
For example:

Docker Image: myenv:v1

        | docker run  ->docker run myenv:v1

myenv:v1

The image remains the same, but every newly created container gets its own unique container ID.

The image is uploaded from our Docker Host to Docker Hub / remote registry.

1. WHAT IS DOCKER?
------------------

Docker is a containerization platform.

It packages an application and all its required dependencies
into a container so that the application can run consistently
in different environments.

Example:

Application
    |
    +-- Java
    +-- Python
    +-- Maven
    +-- Other dependencies
    |
    ---> Docker Container


2. WHY DO WE NEED DOCKER?
--------------------------

PROBLEM 1:

Suppose we have multiple applications.

APP-1 requires Java 8
APP-2 requires Java 11

If both applications are deployed on the same machine,
they may have dependency or version conflicts.

Example:

APP-1 ---> Java 8
APP-2 ---> Java 11

Both applications may not work properly because they
require different Java versions.


PROBLEM 2:

Different applications may require different versions
of the same software.

For example:

Application 1 ---> Java 8
Application 2 ---> Java 11
Application 3 ---> Java 17

Managing different versions on one machine can create
dependency problems.


PROBLEM 3:

RESOURCE UTILIZATION

Suppose a machine has 8 GB RAM.

One application may use only 500 MB RAM.

The remaining resources may not be properly utilized.

If another application is deployed on the same machine,
there can be resource and dependency issues.

Also, when one application is running, it may affect
other applications.


3. VIRTUALIZATION
-----------------

To solve these problems, companies use virtualization.

Virtualization allows us to create multiple Virtual Machines
(VMs) on a single physical machine.

A software called a HYPERVISOR is used to create and run
Virtual Machines.


HYPERVISOR
----------

A hypervisor is software that allows us to create and run
Virtual Machines on a physical machine.


Example:

                PHYSICAL MACHINE
                       |
                  HYPERVISOR
              /        |        \
             /         |         \
           VM-1       VM-2       VM-3
            |           |          |
          OS-1        OS-2       OS-3
            |           |          |
          APP-1       APP-2      APP-3


4. ADVANTAGES OF VIRTUALIZATION
--------------------------------

1. We can run different operating systems on one
   physical machine.

2. We can deploy multiple applications.

3. Applications can have different OS environments.

4. We can use different versions of software.

5. Better isolation between applications.

6. Multiple environments can be created on one
   physical machine.


5. DISADVANTAGES OF VIRTUALIZATION
-----------------------------------

1. Each VM needs its own operating system.

2. Each VM requires CPU and RAM.

3. More resources are consumed.

4. There is resource overhead because every VM has
   a complete OS.

5. VM creation and management can be heavier.

6. Hardware resources may not be efficiently utilized.


Example:

Physical Machine = 8 GB RAM

VM-1 ---> 2 GB RAM
VM-2 ---> 2 GB RAM
VM-3 ---> 2 GB RAM

A significant amount of memory is consumed by the
operating systems themselves.


6. DOCKER
---------

Docker is a containerization platform.

Docker packages the application and all its dependencies
into a container.

The container provides an isolated environment in which
the application can run.


Example:

Application
     |
     +-- Java
     +-- Python
     +-- Maven
     +-- Dependencies
     |
     ---> Docker Container


7. WHY DO WE USE DOCKER?
-------------------------

Main reasons:

1. Easy deployment

2. Application isolation

3. Better resource utilization

4. Dependency management

5. Same environment across different machines

6. Lightweight compared to Virtual Machines


Docker deployment flow:

Dockerfile
    |
    v
Docker Image
    |
    v
Docker Container


8. DOCKER CONTAINER
-------------------

A container is an isolated environment in which an
application runs.

The container contains the application and its required
dependencies.

Example:

Container
   |
   +-- Application
   +-- Java
   +-- Python
   +-- Maven


Container is lightweight compared to a Virtual Machine
because it does not require a complete guest operating
system for every application.

12. DOCKER SERVER / LOCAL REGISTRY
-----------------------------------

The Docker environment can also contain a local registry.

A registry is used to store Docker images.

Docker images can be stored locally or in a remote registry
such as Docker Hub.

Docker Hub is a cloud-based public registry.

- Download Docker images

Docker Hub can be used as a remote registry.

A Docker image is a package/template used to create

Example:

myenv = image name
v1    = image tag/version

17. WHAT HAPPENS DURING DOCKER BUILD?
--------------------------------------

When we execute:

docker build -t myenv:v1 .

Docker reads the Dockerfile instructions.

Example:

FROM ubuntu
       |
       v
Ubuntu base layer

Install Java
       |
       v
Java layer

Install Python
       |
       v
Python layer

Install Maven
       |
       v
Maven layer


These layers are combined to create the final Docker image.


18. DOCKER IMAGE LAYERS
-----------------------

Docker images are built using layers.

For example:

Layer 4 ---> Maven
Layer 3 ---> Python
Layer 2 ---> Java
Layer 1 ---> Ubuntu


Each instruction in the Dockerfile can create a new
filesystem layer.

The final result is a Docker Image.


19. DOCKER RUN
--------------

docker run is used to create and start a new container
from a Docker image.

Example:

docker run -it centos


Here:

docker run = create and start a new container
-it        = interactive terminal
centos     = image name


Another example:

docker run -it centos:7


Here:

centos = image
7     = tag/version


20. docker run VS docker start
------------------------------

docker run:

- Creates a NEW container from an image.
- Starts that new container.

Example:

docker run -it centos


If we execute docker run again:

docker run -it centos

another NEW container will be created.

The image can be the same, but the container ID will be
different.


docker start:

- Starts an EXISTING stopped container.
- It does NOT create a new container.


Example:

docker start <container_id>


IMPORTANT:

docker run  ---> Create + Start NEW container

docker start ---> Start EXISTING stopped container


21. INTERACTIVE TERMINAL (-it)
------------------------------

-i means interactive.

-t means allocate a terminal.

Together:

-it

means we can interact with the container through the
terminal.


Example:

docker run -it centos


After entering the container, we can execute commands
inside it.


22. DOCKER ATTACH
-----------------

If a container is already running and we want to connect
to its terminal:

docker attach <container_id>


Example:

docker attach fa671c640475


This attaches our terminal to the running container.


23. EXIT FROM CONTAINER
-----------------------

If we are inside a container and type:

exit


the container's main process may stop.

Example:

Container is running

       |
       v

       |
       v
exit
       |
       v
Container stops


If we want to detach from the container while keeping it
running, we can use:

CTRL + P
CTRL + Q


This detaches from the container without stopping it.


24. DOCKER STOP
---------------

docker stop is used to stop a running container.

Command:

docker stop <container_id>


Example:

docker stop fa671c640475


After stopping:

Running Container
       |
       v

25. DOCKER START
----------------

If a container is stopped and we want to start the same
container again:

docker start <container_id>


Example:

docker start fa671c640475


Remember:

docker start does NOT create a new container.

It starts the existing stopped container.


26. DOCKER RM
-------------

docker rm is used to remove a container.

Example:

docker rm <container_id>


Usually, a container needs to be stopped before removing it.

Flow:

Running Container
       |
       | docker stop
       v
Stopped Container
       |
       | docker rm
       v
Container Removed


27. FORCE REMOVE CONTAINER
---------------------------

A running container can be forcefully removed using:

docker rm -f <container_id>


Example:

docker rm -f fa671c640475


But normally:

docker stop <container_id>

then:

docker rm <container_id>

35. BASIC DOCKER WORKFLOW
--------------------------

Step 1:
Install Docker on the machine.

Step 2:
Create a Dockerfile.

Step 3:
Specify the required environment and dependencies.

Example:

Ubuntu
Java
Python
Maven

Step 4:
Build the Docker image.

Command:

docker build -t myenv:v1 .

Step 5:
Run the image.

Command:

docker run -it myenv:v1

Step 6:
A container is created and started.

Step 7:
If we want to share the image:

docker push myenv:v1

Step 8:
Another developer can download it:

docker pull myenv:v1

Step 9:
The developer can create a container:

docker run -it myenv:v1

sudo docker run -it centos
Work: Downloads the CentOS image if not available locally, then creates and starts a container.
-it = interactive terminal, so you can enter commands inside the container.

sudo docker run -it centos:7
Work: Runs a CentOS version 7 container interactively.
centos:7 means the image name is centos and the tag/version is 7.

clear
Work: Clears the terminal screen.
It does not affect Docker containers, images, or anything else.

sudo docker ps
Work: Lists currently running Docker containers.
It shows container ID, image, status, ports, and name.

sudo docker attach fa671c640475
Work: Connects your terminal to the running container with this container ID.
You can interact with the process running inside the container.

sudo docker ps
Work: Checks which containers are currently running.
The attached container should appear if it is still running.

sudo docker ps -a
Work: Lists all containers on the Docker host.
It includes running, stopped, and exited containers.

sudo docker start fa671c640475
Work: Starts the existing stopped container with this container ID.
It does not create a new container.

sudo docker ps
Work: Checks whether the started container is now running.
The container should appear in the output.

sudo docker attach fa671c640475
Work: Attaches your terminal to the existing running container.
It allows you to interact with that container again.

clear
Work: Clears the terminal screen.
No Docker resource is changed.

sudo docker run -itd centos:7
Work: Creates and starts a new CentOS 7 container in the background.
-i = interactive, -t = terminal, -d = detached/background mode.

sudo docker ps
Work: Lists the running containers.
The newly created CentOS container should appear here.

sudo docker ps -a
Work: Lists all containers.
It shows both running and stopped/exited containers.

sudo docker rm a07745b4fe63 fa671c640475 c6fe5218dc35 88432bab8e60 80df1dfaf231
Work: Removes the specified containers.
Normally, containers must be stopped before they can be removed; use "docker rm -f" if you intentionally want to force removal.

sudo docker ps
Work: Shows currently running containers.
Removed containers will not appear.

sudo docker stop a07745b4fe63
Work: Gracefully stops the running container with this ID.
The container is stopped but still exists.

sudo docker rm a07745b4fe63
Work: Removes the stopped container.
The container is deleted, but its image is not deleted.

sudo docker ps -a
Work: Checks all remaining containers.
The removed container should no longer appear.

clear
Work: Clears the terminal screen.
It does not change Docker resources.

sudo docker run -itd centos:7
Work: Creates and starts another CentOS 7 container in detached mode.
If the image already exists locally, Docker uses the local image.

sudo docker ps -a
Work: Lists all containers.
You can see the newly created CentOS 7 container and its status.

sudo docker images
Work: Lists Docker images stored locally.
It shows repositories, tags, image IDs, and sizes.

sudo docker rmi centos:7
Work: Removes the CentOS 7 image from the local image store.
It will fail if a container still depends on that image; remove the containers first.

sudo docker ps
Work: Lists running containers.
It does not list Docker images.

sudo docker rmi centos:7
Work: Tries to remove the CentOS 7 image again.
If a container still references the image, Docker will normally refuse the removal.

sudo docker ps -a
Work: Lists all containers, including stopped containers.
Use this to find containers that may still reference centos:7.

sudo docker rm 61cd5221e4ca
Work: Removes the specified container.
After removing it, the CentOS image may become removable if no other container references it.

sudo docker rmi centos:7
Work: Removes the CentOS 7 image from the local system.
The image can now be removed if no containers are using it.

sudo docker images
Work: Lists the remaining local Docker images.
centos:7 should no longer be listed.

sudo docker rmi hello-world
Work: Removes the hello-world image from the local image store.
It does not remove containers created from the image.

clear
Work: Clears the terminal screen.
Docker resources remain unchanged.

sudo docker images
Work: Lists all Docker images available locally.
You can check whether httpd, tomcat, jenkins, etc. are present.

sudo docker run -itd httpd
Work: Creates and starts an Apache HTTP Server container in detached mode.
If httpd is not local, Docker pulls the image from the configured registry, commonly Docker Hub.

sudo docker ps
Work: Lists currently running containers.
The httpd container should appear if it started successfully.

sudo docker run -itd tomcat
Work: Creates and starts a Tomcat container in detached mode.
Docker pulls the Tomcat image if it is not already available locally.

sudo docker run -itd jenkins
Work: Creates and starts a Jenkins container using the jenkins image/tag requested.
If the image is not local, Docker attempts to pull it from the configured registry.

sudo docker run -itd jenkins2.x
Work: Tries to run an image named "jenkins2.x".
If that image does not exist locally or in the configured registry, the command will fail.

sudo docker run -itd jenkins 2.x
Work: Docker interprets "jenkins" as the image and "2.x" as an invalid extra argument.
This is not the correct way to specify a Jenkins version.

clear
Work: Clears the terminal screen.
No Docker resource is changed.

sudo docker run -itd jenkins:2.60.3
Work: Creates and starts a Jenkins container using the specific image tag 2.60.3.
jenkins = repository/image name, 2.60.3 = image tag/version.

sudo docker ps
Work: Lists the currently running containers.
You can verify whether the Jenkins container is running.

history
Work: Displays the commands previously executed in the shell.
