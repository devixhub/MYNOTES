TERRAFORM 
--------------
"Terraform is used for infrastructure provisioning, while Ansible is used for configuration management. 
Terraform creates the server and other cloud resources, and Ansible configures the server after it has been created.
| Feature           | Ansible                                                  | Terraform                                        |
| ----------------- | -------------------------------------------------------- | ------------------------------------------------ |
| Primary purpose   | Configuration management and application deployment      | Infrastructure provisioning                      |
| Approach          | Procedural (step-by-step tasks)                          | Declarative (describe desired state)             |
| Typical use       | Install software, configure servers, deploy applications | Create cloud resources, networks, VMs, databases |
| State management  | No central state required                                | Maintains a state file                           |
| Agent requirement | Agentless (SSH/WinRM)                                    | Uses cloud/provider APIs                         |
| Idempotency       | Supported through modules                                | Core design principle                            |
| Best for          | Managing what's *inside* servers                         | Managing the infrastructure itself               |
rraform is mainly used for Infrastructure as Code (IaC), which means creating and managing infrastructure resources such as EC2 instances, VPCs, subnets, load balancers, and databases. It works using a declarative approach and maintains a state file to track infrastructure.

Ansible is mainly used for configuration management and application deployment.
 It is agentless and connects to servers using SSH to install packages, configure services, and deploy applications.
In a real-world scenario, 
I would use Terraform to provision an EC2 instance and Ansible to install and configure software like Nginx,
 Apache, or application code on that instance."

1. terraform init

Purpose: Initializes the Terraform project.

Downloads the required provider plugins (e.g., AWS).
Creates the .terraform directory.
Run this first after creating or cloning a Terraform project.
2. terraform validate

Purpose: Checks whether the Terraform configuration is syntactically correct.

Finds errors in your .tf files.
Does not create any resources.
3. terraform plan

Purpose: Shows what Terraform will do before making changes.

Displays which resources will be created, modified, or deleted.
Helps you review the changes safely.
4. terraform apply

Purpose: Creates or updates the infrastructure.

Executes the changes shown in terraform plan.
Creates resources such as EC2 instances, VPCs, subnets, etc.
5. terraform destroy

Purpose: Deletes all infrastructure managed by Terraform.

Removes the resources created by your Terraform configuration.
Useful for cleaning up test environments and avoiding unnecessary cloud costs.

===============================
HOW TERRAFORM UPDATES INFRASTRUCTURE
===============================

Terraform ensures that your infrastructure always matches the Desired State.

------------------------------------
1. Desired State
------------------------------------

- The DevOps Engineer writes Terraform code in .tf files.
- These .tf files define the infrastructure you want to create.

Example:
EC2 Instance
VPC
Subnet
S3 Bucket
Security Group
IAM Role

------------------------------------
2. Terraform Apply
------------------------------------

Command:

terraform apply

Terraform compares:

Desired State (.tf files)

            VS

Actual State (Current Infrastructure)

It identifies the differences and performs the required actions.

Terraform can:
- Create resources
- Update resources
- Delete resources

------------------------------------
3. terraform.tfstate
------------------------------------

After applying the changes, Terraform updates the

terraform.tfstate

This file stores the current state of the infrastructure managed by Terraform.

------------------------------------
4. Infrastructure Matches State
------------------------------------

After the apply operation:

Desired State = Actual State

The infrastructure now exactly matches the Terraform code.

====================================
WHAT IS terraform.tfstate?
====================================

terraform.tfstate stores the current state of the infrastructure managed by Terraform.

It helps Terraform:
- Track resources
- Detect changes
- Compare desired state with actual state
- Update infrastructure efficiently

Note:
Never edit the terraform.tfstate file manually.

====================================
KEY POINTS
====================================

• .tf files define the Desired State.
• terraform.tfstate stores the Actual State.
• Terraform compares Desired State with Actual State.
• Terraform only makes the required changes.
• Store the state file securely (Amazon S3, GCS, Azure Storage) for team collaboration.
• Desired State and Actual State should always remain synchronized.

tf files with the Actual State stored in the terraform.tfstate file. It identifies the differences,
 creates, updates, or deletes resources as needed, and then updates the terraform.tfstate file so that
 the Actual State matches the Desired State.

 lockfile
 ---------
 ===============================
use_lockfile = true (Terraform)
===============================

What is use_lockfile = true?

use_lockfile = true enables state locking for the Terraform state file.

It ensures that only one user or process can modify the Terraform state file at a time.

------------------------------------
Why do we use it?
------------------------------------

Without state locking:

- User A runs terraform apply.
- At the same time, User B also runs terraform apply.
- Both users try to update the same terraform.tfstate file.
- This can cause:
  • State file corruption
  • Resource conflicts
  • Infrastructure inconsistency

With state locking:

- User A acquires the lock and starts the deployment.
- User B tries to run terraform apply.
- Terraform blocks User B and displays a state lock error.
- After User A finishes, Terraform releases the lock.
- User B can then run terraform apply.

------------------------------------
Example
------------------------------------

terraform {
  backend "s3" {
    bucket        = "my-terraform-state"
    key           = "dev/terraform.tfstate"
    region        = "ap-south-1"
    encrypt       = true
    use_lockfile  = true
  }
}

------------------------------------
How it Works
------------------------------------

DevOps Engineer A
        │
        ▼
terraform apply
        │
        ▼
Lock Acquired
        │
        ▼
terraform.tfstate Updated
        │
        ▼
Lock Released

At the same time...

DevOps Engineer B
        │
        ▼
terraform apply
        │
        ▼
Error: State is locked
        │
        ▼
Wait until the lock is released

------------------------------------
Benefits
------------------------------------

✔ Prevents multiple users from modifying the state file simultaneously.
✔ Prevents state file corruption.
✔ Ensures only one terraform apply runs at a time.
✔ Makes Terraform safe for team collaboration.

------------------------------------
Interview Answer
------------------------------------

use_lockfile = true enables state locking for the Terraform state file.
 It ensures that only one user or process can modify the state file at a time.
 If another user tries to run Terraform while the state is locked,
 Terraform blocks the operation until the lock is released. This prevents state corruption and infrastructure conflicts.

------------------------------------
Easy Example
------------------------------------

Suppose three DevOps engineers are working on the same project.

Devi  ---> terraform apply ---> Lock Acquired ✅

Rahul ---> terraform apply ---> State is Locked ❌

Amit  ---> terraform apply ---> Wait until the lock is released ⏳

After Devi's deployment is completed, Terraform releases the lock, and Rahul or Amit can run terraform apply safely.
