1/- EXPLAIN END TO END WORKFLOW TO DEPLOY AND DELETE RESOURCE IN CLOUD ?

First, I write the Terraform configuration for the resources I want to create.
 Then I run terraform init to initialize the project and download the required provider. 
After that, I run terraform validate to format and check my configuration.

Then I run terraform plan, which shows me what Terraform is going to create,
 modify, or delete. If everything looks correct, I run terraform apply. 
 Terraform then communicates with the cloud provider, for example AWS
 , and creates the required resources. Terraform also maintains the state of those resources in the state file.

When I no longer need the resources, I can first run terraform plan -destroy to preview the deletion,
 and then run terraform destroy. Terraform will delete the resources that it manages and update the state accordingly.

2/-WHAT IS TERRAFORM STATE FILE AND WHY WE DON'T STORE IT IN GIT ?

Terraform state file is used by Terraform to keep track of the resources it manages and their current state
the state file is not a history or log,It primarily represents the current known state
it created when we command terraform plan , it stores aws resource id , ami ,instance-type , tag name
for security reason we don't upload it in git .
