Jenkins
===============================
============================================================
JENKINS ARCHITECTURE - END TO END WORKFLOW
============================================================

INTERVIEW ANSWER
----------------

If the interviewer asks, "Explain Jenkins architecture and its
end-to-end workflow", I would answer like this:

"Jenkins follows a Controller-Agent architecture. The Jenkins
Controller is responsible for managing Jenkins, scheduling jobs,
managing users, security, credentials, plugins and agents.

The actual build, test and deployment work is normally executed
by Jenkins Agents. The Controller selects a suitable Agent and
assigns the job to it.

In a real CI/CD project, the developer pushes code to GitHub.
GitHub can trigger Jenkins through a webhook. Jenkins receives
the trigger, starts the required job or pipeline, and gets the
source code from GitHub.

If we are using a Jenkinsfile, Jenkins reads the Jenkinsfile from
the repository and executes the pipeline stages. The Controller
assigns the pipeline to a suitable Agent.

The Agent then performs the actual tasks such as Git checkout,
Maven build, testing, packaging and deployment. After execution,
the Agent sends the build result back to the Controller, and
Jenkins shows the result in the dashboard and console output."

============================================================
MAIN COMPONENTS
============================================================

1. JENKINS CONTROLLER
---------------------

The Controller is the main Jenkins server.

It is responsible for:

- Managing Jenkins
- Creating and managing jobs
- Scheduling builds
- Managing Agents
- Managing Plugins
- Managing Users
- Managing Security
- Managing Credentials
- Maintaining Jenkins configuration

The Controller mainly manages and coordinates the work.

------------------------------------------------------------

2. JENKINS AGENT
----------------

Agent is the machine where the actual job execution happens.

For example:

Linux Agent
    ↓
Git checkout
    ↓
Maven build
    ↓
Testing

Windows Agent
    ↓
Windows-specific build
    ↓
Testing

The Agent performs the actual commands required by the job.

------------------------------------------------------------

3. EXECUTOR
-----------

An Executor is a slot on an Agent that can execute one task.

Example:

Linux Agent
Executors = 2

Executor 1 → JOB_1
Executor 2 → JOB_2

If both executors are busy, another job waits in the queue.

------------------------------------------------------------

4. WORKSPACE
------------

Workspace is the directory on the Agent where Jenkins keeps the
source code and performs the build.

Example:

/var/lib/jenkins/workspace/JOB_NAME

The source code is checked out into the workspace.

============================================================
END TO END CI WORKFLOW
============================================================

STEP 1
------

Developer writes or modifies application code.

Example:

Java / Spring Boot application

------------------------------------------------------------

STEP 2
------

Developer pushes the code to GitHub.

Example:

git add .
git commit -m "Update application"
git push

------------------------------------------------------------

STEP 3
------

GitHub triggers Jenkins.

This can happen through:

GitHub Webhook
Poll SCM
Manual Trigger
Remote Trigger

For a typical GitHub CI workflow:

GitHub
   ↓
Webhook
   ↓
Jenkins

------------------------------------------------------------

STEP 4
------

Jenkins Controller receives the trigger.

The Controller identifies which Jenkins job or Pipeline should
run.

------------------------------------------------------------

STEP 5
------

Jenkins checks whether an Agent is available.

Example:

Linux Agent → Online
Executor → Available

If the Agent is not available, Jenkins may keep the build in the
queue until a suitable Agent becomes available.

------------------------------------------------------------

STEP 6
------

Controller assigns the job to the Agent.

Example:

JOB_1
   ↓
Linux Agent

------------------------------------------------------------

STEP 7
------

Agent creates/uses the Jenkins workspace.

Example:

/var/lib/jenkins/workspace/JOB_1

------------------------------------------------------------

STEP 8
------

Jenkins checks out the source code from GitHub.

Flow:

GitHub
   ↓
Jenkins Agent
   ↓
Workspace

------------------------------------------------------------

STEP 9
------

If the project uses a Jenkinsfile, Jenkins reads the Jenkinsfile
and starts executing the Pipeline.

Example Jenkinsfile:

pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                sh 'mvn compile'
            }
        }
    }
}

------------------------------------------------------------

STEP 10
-------

Jenkins executes the Pipeline stages.

Typical stages:

Checkout
   ↓
Compile
   ↓
Test
   ↓
Package
   ↓
Deploy

------------------------------------------------------------

STEP 11
-------

Maven builds the application.

Example:

mvn compile

Then:

mvn test

Then:

mvn package

------------------------------------------------------------

STEP 12
-------

If all stages are successful, the application artifact is
created.

Example:

JAR
WAR

Example:

target/application.jar

------------------------------------------------------------

STEP 13
-------

The application can then be deployed to the required environment.

Example:

Jenkins
   ↓
Tomcat / Server / Cloud

------------------------------------------------------------

STEP 14
-------

The Agent sends the execution result back to the Jenkins
Controller.

Result can be:

BUILD SUCCESS

or

BUILD FAILURE

------------------------------------------------------------

STEP 15
-------

Jenkins displays the result in:

Build History
Console Output
Pipeline View

============================================================
ROLE OF CONTROLLER AND AGENT
============================================================

CONTROLLER
----------

Controller decides:

"What job should run?"

"Which Agent should run it?"

"How should Jenkins manage this job?"

AGENT
-----

Agent performs:

"Run Git."

"Run Maven."

"Run tests."

"Create the artifact."

"Perform deployment."

Easy way to remember:

Controller = MANAGE + SCHEDULE

Agent = EXECUTE

============================================================
WHY DO WE USE CONTROLLER-AGENT ARCHITECTURE?
============================================================

1. Workload Distribution
------------------------

Instead of running every job on one machine, Jenkins distributes
the work to Agents.

------------------------------------------------------------

2. Parallel Execution
---------------------

Multiple Agents can execute different jobs at the same time.

Example:

Linux Agent  → JOB_1
Windows Agent → JOB_2

------------------------------------------------------------

3. Different Environments
-------------------------

We can have:

Linux Agent
Windows Agent
Docker Agent

Each job can run in the required environment.

------------------------------------------------------------

4. Scalability
--------------

If the number of builds increases, we can add more Agents.

============================================================
INTERVIEW ANSWER - EASY VERSION
============================================================

"Jenkins follows a Controller-Agent architecture. The Controller
is the main Jenkins server and it manages jobs, schedules builds,
and manages users, security, credentials, plugins and Agents.

The Agents are the machines where Jenkins executes the actual
build, test and deployment tasks.

For example, when a developer pushes code to GitHub, GitHub sends
a webhook to Jenkins. The Jenkins Controller receives the trigger,
identifies the Pipeline, selects a suitable Agent and assigns the
job to it.

The Agent checks out the code into its workspace and executes the
Jenkinsfile stages such as compile, test, package and deployment.
After the job finishes, the result is sent back to the Controller
and Jenkins displays whether the build was successful or failed."
